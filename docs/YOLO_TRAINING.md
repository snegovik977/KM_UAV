# Обучение YOLO для обнаружения станций

Собрано: 2026-08-01. Источники: [документация Geoscan «Модели ИИ»][ai-models] и
[Pioneer-RKNN][pio-rknn], README форка [airockchip/ultralytics_yolo11][fork],
полевой опыт другой команды на этом же дроне
([lessons_from_archipelago.md](lessons_from_archipelago.md) §2, §4).
Собственные выводы отделены пометкой «наше решение».

Инструкция закрывает весь путь: от съёмки кадров до `detector.backend: yolo` на борту.
Восемь шагов, каждый — одна команда. Что зачем — в [DRONE_PLAN.md](DRONE_PLAN.md) §2.1.

> **Классический CV никуда не девается.** `detector.backend: classic` остаётся рабочим
> и служит фолбэком: если модель не поднялась (нет `pioneer_rknn`, нет модели в реестре),
> `create_detector` сам падает на классический и громко об этом говорит. Обнулить
> подзадачу 2.3.2 неудачной моделью нельзя — только ухудшить качество.

## 0. Коротко: весь конвейер

```bash
# ── на машине с обучением ────────────────────────────────────────────────────
python training/extract_frames.py records/*.mp4            # 1. кадры из записей
python training/label.py                                   # 2. разметка мышью
python training/build_dataset.py                           # 3. train/val + data.yaml
python training/train.py                                   # 4. обучение
python training/check_model.py                             # 5. проверка глазами
python training/export_onnx.py                             # 6. raw-branch ONNX
python training/rknn/make_calib.py                         # 7. кадры для INT8
training/rknn/convert.sh training/runs/stations/weights/best.onnx
python training/upload_model.py training/rknn/stations_rk3576_int8raw.rknn

# ── на борту, до полёта ──────────────────────────────────────────────────────
python3 tools/diag_model.py --model stations               # 8. девять сырых веток?
python3 tools/handheld.py                                  #    рамки над станциями
```

Затем в `квадрокоптер/config.yaml`: `detector.backend: yolo`.

## 1. Окружение

Обучение живёт в **отдельном venv**: `torch` тянет за собой полгигабайта и не должен
попадать в `requirements.txt` проекта, который ставится в том числе на выданную машину.

```bash
uv venv --python 3.12 training/.venv
uv pip install --python training/.venv/bin/python -r training/requirements.txt
```

Без `uv`: `python3.12 -m venv training/.venv && training/.venv/bin/pip install -r training/requirements.txt`.

Дальше все команды — этим питоном: `training/.venv/bin/python training/train.py ...`
(или `source training/.venv/bin/activate`).

Python именно 3.12: под 3.14 колёс `torch` нет, системный 3.9 отстаёт от свежих
`ultralytics`. **На борт из этого не ставится ничего** — там модель исполняет
предустановленный `pioneer_rknn`.

Ещё две вещи ставятся один раз:

| Что | Зачем | Команда |
| --- | --- | --- |
| форк `airockchip/ultralytics_yolo11` | экспорт ONNX без decode-головы (§6) | `git clone --depth 1 https://github.com/airockchip/ultralytics_yolo11.git training/vendor/ultralytics_yolo11` |
| Docker | `rknn-toolkit2` есть только под x86-64 Linux (§7) | образ соберётся сам при первом `convert.sh` |

Предобученные веса `yolo11n.pt` лежат в `training/weights/` **в репозитории**
намеренно: на площадке интернета может не быть, а без них обучение не стартует.

## 2. Съёмка датасета

**Чем снимать.** Кадром с камеры дрона, 1080×720. Проще всего — `tools/handheld.py --record`:
дрон носят на руках, винты не крутятся, попытка на полигоне не тратится (регламент 1.3).
Второй источник — обычные записи полётов `records/flight_*.mp4`.

> ⚠️ **Телефонные снимки для обучения не годятся.** У них другой угол обзора и другой
> масштаб; сеть, обученная на них, на борту просядет непредсказуемо. Девять фотографий
> организаторов в `фото станции/` — материал для глаза, а не для обучения.

> ⚠️ **Записи до 2026-08-01 непригодны**: `main.py` писал в видео кадр **уже с рамками
> детектора и полосой HUD**, а сеть выучит нарисованную рамку как признак станции.
> Исправлено: `mission.record_raw: true` пишет сырой кадр. Полосу HUD у старых записей
> можно срезать (`extract_frames.py --crop-top 24`), рамки — нельзя ничем, такие кадры
> годятся только в негативы.

**Что снимать** (наше решение, выведено из разбора площадки в `CLAUDE.md`):

- 300–500 кадров, хорошо — 500+;
- **высоты 1.2–2.5 м**: порог площади на борту считается в м², но сама сеть должна
  видеть станцию и мелкой, и крупной;
- **все ориентации станции**: съёмка сверху, панель может лежать под любым углом;
- **разное освещение**: тени от людей и конструкций, засветка от ламп;
- **20–30 % кадров без станций вообще** — это не брак, а самая ценная часть датасета
  (см. §3);
- **обязательно `dust`**: не меньше трети боксов, иначе класс не выучится.

```bash
python training/extract_frames.py records/*.mp4              # каждый 5-й кадр
python training/extract_frames.py records/flight_20260802_*.mp4 --stride 3 --max 150
python training/extract_frames.py "фото площадки" --clip площадка
```

Кадры раскладываются по **клипам** — папка на съёмку. Клип это не украшение: по клипам
делается сплит train/val (§4). Похожие подряд идущие кадры отбрасываются (`--diff`):
пока дрон висит на месте, в датасет попадёт один кадр, а не сорок одинаковых.

## 3. Разметка

```bash
python training/label.py                    # все клипы
python training/label.py --clip 083847      # свой клип: команда размечает параллельно
python training/label.py --only-unlabeled   # продолжить с того места, где бросили
```

Управление показано прямо в окне: **ЛКМ протянуть** — рамка, **ПКМ** — удалить,
**1/2** — класс (`ok` / `dust`), **пробел** — дальше, **X** — кадр без станций, **Q** — выход.
Формат — YOLO, `.txt` рядом с картинкой; ничего, кроме `opencv`, не требуется (на выданной
машине CVAT или labelImg может просто не поставиться — регламент 1.4).

**Правила разметки** (наше решение; от них зависит, что сеть посчитает станцией):

| Ситуация | Как размечать |
| --- | --- |
| Панель целиком в кадре | рамка по краю панели, **вместе с радужной рамкой**, без тени |
| На панели лежат цветные многогранники | класс `dust` — хоть один многогранник |
| Панель чистая | класс `ok` |
| Многогранник/мусор лежит **рядом** на полу | не размечать вообще — это фон |
| Панель видна частично у края кадра | размечать по видимой части |
| Логотип «ТЕХНОБОТ», разметка трассы, посадочный знак «H», серые комки | **не размечать**, и такой кадр обязательно сохранить (клавиша X, если станций нет) |

Последняя строка — самая важная. Белый логотип на покрытии и серые комки мусора это
**подтверждённые** ложные срабатывания классического детектора (`CLAUDE.md`, разбор
фотографий 01.08.2026). Сеть перестанет на них реагировать только если увидит их
в кадрах, размеченных как фон.

**Эталон разметки уже лежит в репозитории.** Девять снимков организаторов размечены
руками как образец правил выше — пять `dust`, четыре `ok`, мусор рядом с панелями
не размечен:

```bash
python training/extract_frames.py "фото станции" --clip organizers_phone --diff 0
python training/label.py --clip organizers_phone --review
```

Первая команда нужна потому, что в git лежит только разметка (`.txt`) — кадры
игнорируются как тяжёлые, а имена восстанавливаются детерминированно.

В обучение этот клип **не идёт** (он в `training/skip_clips.txt`): снят телефоном,
оптика и масштаб не те. Смотреть на него — можно и нужно, учить на нём — нет.

Со второго круга разметка ускоряется предсказаниями прошлой модели:

```bash
python training/label.py --prelabel training/runs/stations/weights/best.pt
```

Черновые рамки показываются, но **сами не сохраняются** — только когда вы их тронули.
Иначе ошибки модели молча уедут в датасет и закрепятся при следующем обучении.

## 4. Сборка датасета

```bash
python training/build_dataset.py
python training/build_dataset.py --val-clips 083847      # val выбирается руками
```

Скрипт собирает `training/dataset/{images,labels}/{train,val}` и пишет `data.yaml`.

**Сплит делается по клипам, а не по кадрам.** Соседние кадры одного пролёта отличаются
на дрожание руки; при случайном разбиении они попадают и в train, и в val, сеть их
запоминает, и mAP показывает 0.95 на модели, которая на площадке не видит ничего.
Ровно на этом обжигалась команда с того же соревнования
([lessons_from_archipelago.md](lessons_from_archipelago.md) §4). Какие клипы уходят
в val — задаётся `--val-clips` или файлом `training/val_clips.txt`; правильный val это
клип, максимально похожий на зачётную попытку.

Кадр **без** `.txt` в датасет не идёт вообще: он «ещё не размечен», а не «пустой».
Пустой `.txt` — идёт, это проверенный негатив.

Скрипт ругается на то, что дороже всего стоит: пустой val, меньше 150 кадров, мало
негативов, редкий класс, расхождение `classes.txt` с `detector.labels` борта.

## 5. Обучение

```bash
python training/train.py                      # 100 эпох, imgsz 640
python training/train.py --epochs 200 --batch 8
```

Модель — **YOLO11n**, самая мелкая: инференс идёт на борту в общем цикле с полётом,
и что-то крупнее просто не успеет (`detector.every_n` в `config.yaml` уже прореживает
инференс до каждого третьего кадра).

Аугментации в `train.py` заданы под нашу задачу, и два отличия от умолчаний
принципиальны (наше решение, обоснование — [DRONE_PLAN.md](DRONE_PLAN.md) §3.2):

- **`hsv_h=0.0` — оттенок не трогаем.** «Покрыта пылью» на этой площадке изображается
  цветными многогранниками, положенными на панель, то есть класс кодируется **цветом**.
  Jitter по оттенку травит ровно тот признак, по которому классы и различаются.
- **`hsv_v=0.4` — яркость крутим смело.** Освещение меняется от попытки к попытке,
  а класс от него не зависит.
- `degrees=180`, `flipud=0.5` — вид сверху: любая ориентация станции валидна.
- `scale=0.5` — высоты полёта 1.2–2.5 м меняют размер станции в кадре вдвое.

`imgsz=640` обязан совпадать с `detector.img_size` в `config.yaml` и со входом `.rknn`.
Меняете — меняйте во всех трёх местах.

### 5.3. Проверка до конвертации

```bash
python training/check_model.py                  # mAP + картинки с рамками
python training/check_model.py --conf 0.15
```

Смотреть **картинки**, а не только mAP. Две вещи, которые mAP не покажет:

1. что модель считает станцией лишнего (логотип, «H», мусор) — лечится негативами в датасете;
2. путает ли она `ok` и `dust` — это различие самое хрупкое, и первым ломается при
   INT8-квантовании. Эталон снимаем **здесь**, чтобы после конвертации было с чем сравнить.

Хорошие веса сразу копируем с версией в имени: `cp training/runs/stations/weights/best.pt
training/weights/stations_v1.pt` — `training/runs/` в git не идёт.

## 6. Экспорт ONNX — единственное место, где легко потерять день

```bash
python training/export_onnx.py
python training/export_onnx.py --check какой-нибудь.onnx    # только проверить
```

> 🔴 **Обычный экспорт ONNX не годится.** Стандартная голова YOLO отдаёт один плоский
> тензор `1 × (4+nc) × 8400` с decode внутри графа. После INT8-квантования такая модель
> на борту даёт **ровно ноль детекций и ни одной ошибки** — DFL-часть не квантуется.
> Проверено другой командой на этом же железе
> ([lessons_from_archipelago.md](lessons_from_archipelago.md) §2).

Рабочий путь — форк [airockchip/ultralytics_yolo11][fork]: при `format='rknn'` его голова
отдаёт **девять сырых веток**, по три на масштаб:

| Ветка | Форма | Что это |
| --- | --- | --- |
| box-DFL | `[1, 64, H, W]` | 4 стороны × 16 бинов |
| классы | `[1, nc, H, W]` | уже после sigmoid |
| score-sum | `[1, 1, H, W]` | служебная, для быстрой отбраковки |

Разбирает их наш декодер **на CPU борта** — `perception/detector.py → decode_rawbranch`.
`export_onnx.py` делает экспорт и **сразу проверяет структуру файла**: если голова
оказалась плоской или число классовых каналов не то, он говорит это словами.

Три вещи, которые ломаются здесь молча:

1. **`.rknn` и декодер — пара.** Raw-branch модель с плоским декодером даёт мусор,
   плоская модель с нашим декодером — пустоту. Обе — без единой ошибки. Версионировать
   и заливать вместе.
2. **Классов должно быть ≥ 2.** При одном классе классовая ветка имеет 1 канал — ровно
   как score-sum, а ветки опознаются **по числу каналов** (RKNN их переставляет, порядку
   верить нельзя). Поэтому в `classes.txt` два класса даже там, где статус не нужен.
3. **`classes.txt` = `detector.labels`** в `config.yaml`. Расхождение — не ошибка
   загрузки, а неверные боксы в полёте. `build_dataset.py` сверяет это и ругается.

## 7. Конвертация в `.rknn` и заливка на борт

```bash
python training/rknn/make_calib.py                                    # ~200 кадров
training/rknn/convert.sh training/runs/stations/weights/best.onnx
```

`rknn-toolkit2` существует **только под x86-64 Linux**, поэтому конвертация идёт
в контейнере; на Apple Silicon — через эмуляцию, первый прогон долгий.

- **чип `rk3576`** — не догадка: `check_sdk.py` прочитал на нашем борту
  `geoscan,pioneermini2 rockchip,rk3576`. Инструкции под `rk3566` относятся к другому дрону;
- **калибровка INT8 идёт по нашим кадрам**: диапазоны яркости тёмного покрытия площадки
  не похожи ни на что готовое;
- **`mean=0, std=255`** — ultralytics учит на RGB и пикселях 0..1. Камера борта отдаёт
  **BGR**, поэтому в `detector.py` стоит `cvtColor`; без него сеть работает, но заметно
  хуже, и это легко списать на «недоучена»;
- если INT8 «съел» различие `ok`/`dust` — пересобрать без квантования:
  `RKNN_QUANT=0 training/rknn/convert.sh ...` (файл крупнее, инференс медленнее, точность выше).

Заливка и регистрация:

```bash
python training/upload_model.py training/rknn/stations_rk3576_int8raw.rknn
python training/upload_model.py --list          # что уже в реестре борта
```

> 🔴 **Архитектуру при регистрации указывать `custom`**, а не `yolov11`. С `yolov8`/`yolov11`
> `ModelContainer` постобработает выход сам — кодом, который ждёт плоскую голову, — и наш
> декодер сырых веток не увидит ничего. Скрипт ставит `custom` сам; если заливаете руками
> через `http://172.17.49.2:7777/`, это поле надо поменять.

## 8. Проверка на борту и включение

```bash
# на борту
python3 tools/diag_model.py --model stations     # формы выходов + BGR/RGB
python3 tools/handheld.py                        # рамки над реальными станциями, без взлёта
```

`diag_model.py` отвечает на «детекций ноль, а почему» — он различает три причины,
которые вслепую неразличимы: плоская голова, неверная архитектура в реестре,
перепутанные BGR/RGB.

Только после этого — в `квадрокоптер/config.yaml`:

```yaml
detector:
  backend: yolo
  model: stations
  labels: "ok,dust"
  conf: 0.25            # подобрать по борту: ложные против пропусков
```

и проверить прогон целиком: `python launch.py --task 2.3.2 --takeoff --viz`.

## 9. Что делать, если

| Симптом | Причина | Что делать |
| --- | --- | --- |
| На борту **ноль детекций, ни одной ошибки** | плоская голова / арх. не `custom` / BGR вместо RGB | `tools/diag_model.py --model stations` — он различает все три |
| `create_detector` пишет «падаю на классический» | модели нет в реестре или `pioneer_rknn` не поднялся | `python training/upload_model.py --list` |
| mAP высокий, на площадке слепая | сплит был не по клипам | `build_dataset.py --val-clips <другой клип>`, переобучить |
| Много ложных: логотип, «H», мусор | в датасете нет негативов | доснять и разметить кадры без станций (клавиша X) |
| `dust` не отличается от `ok` | класс редкий, или INT8 съел цвет | доснять запылённые; сравнить с `.pt` (§5.3); `RKNN_QUANT=0` |
| Станция то одна, то две в реестре | не детекция, а склейка: `detector.close_m`, `fusion.assoc_radius` | `RUN.md` §7, счётчик `prevented_splits` в итоге |
| `export_onnx.py`: «нет форка» | форк не склонирован | команда в §1 |
| `convert.sh`: docker не отвечает | демон не запущен | `orb start` (OrbStack) или Docker Desktop |

## 10. Что уже проверено сквозным прогоном

01.08.2026 конвейер прогнан целиком на девяти эталонных кадрах (`organizers_phone`,
3 эпохи, `imgsz 320`) — не ради качества модели, а чтобы каждый шаг споткнулся здесь,
а не на площадке. Что подтверждено:

| Шаг | Результат |
| --- | --- |
| `build_dataset.py` | сплит по клипам, `data.yaml`, предупреждения о малом наборе |
| `train.py` | обучение доходит до `best.pt`, MPS подхватывается |
| `export_onnx.py` | **девять сырых веток** `[1,64,H,W] / [1,2,H,W] / [1,1,H,W]` на трёх масштабах |
| `decode_rawbranch` (борт) | те же выходы разбирает и отдаёт валидные боксы и классы |

Последняя строка — главная: экспорт и бортовой декодер **согласованы**, а именно их
рассогласование даёт «ноль детекций без единой ошибки».

Заодно всплыли и закрыты три вещи, каждая из которых стоила бы часа на площадке:
форку нужны `tqdm`/`py-cpuinfo`/`pandas`/`seaborn` (свежий ultralytics их не тянет),
`torch>=2.9` требует `onnxscript`, а `tools/handheld.py --record` падал на первом
