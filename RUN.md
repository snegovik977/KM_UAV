# Как всё это запускать

Пошаговая инструкция: что запускать, в каком порядке, как залить на дрон и что делать,
когда не работает. Простыми словами, без предположений о том, что вы помните архитектуру.

Проверено на этой машине 31.07.2026: Windows, Python 3.11.9, тесты `127 passed`,
полный прогон миссии в заглушке — около минуты.

Что за чем стоит и почему — в [docs/DRONE_PLAN.md](docs/DRONE_PLAN.md). Здесь — только кнопки.

---

## 0. Короткий путь: пульт

Всё, что описано ниже вручную, умеет делать один файл — `launch.py`. Он на стандартной
библиотеке и без bash, так что запускается и на Windows выданной машины:

```bash
python launch.py --mock      # весь прогон на своей машине, борт не нужен
python launch.py             # борт: ключ -> заливка -> хаб -> дрон
python launch.py --push      # только залить код и выйти
```

**Какую подзадачу сдаём — выбирается ключом `--task`.** Это первое, что надо решить
перед запуском, потому что подзадачи ведут себя по-разному:

```bash
python launch.py --task 2.3.1            # облёт по команде. Детекции НЕТ ВООБЩЕ
python launch.py --task 2.3.2 --viz      # + поиск станций и карта визуализатора
python launch.py --task 2.3.3 --viz      # + отправка статусов станций
```

Без ключа берётся `mission.task` из `квадрокоптер/config.yaml` (сейчас там `2.3.1`).
В 2.3.1 детектор и реестр не создаются совсем — ложная детекция физически не может
испортить попытку, которой она не нужна. Подробности профилей — `квадрокоптер/tasks.py`.

Для 2.3.2 и 2.3.3 **визуализатор обязателен**: баллы дают за то, что станции видны
на карте в реальном времени. Ключ `--viz` поднимает его вместе с остальным.

Что он делает сам:

1. проверяет, пускает ли борт по ssh-ключу; если нет — предлагает создать ключ
   и кладёт его на борт (**пароль борта спрашивают один раз, дальше молча**);
2. спрашивает «перезалить код?» и заливает — с `protocol/`, `tools/` и сносом `__pycache__`;
3. **гасит забытые `main.py`/`hub.py` на борту** — это снимает половину случаев
   «камера занята» из §10;
4. поднимает хаб (по умолчанию **на борту**, §8.4 — брандмауэр Windows не мешает),
   дожидается `/health`;
5. запускает дрона и показывает вывод обоих процессов с префиксами `[хаб]` и `[дрон]`;
6. принимает команды: `t` — взлёт (обычный пакет протокола, тот же, что шлёт
   передатчик), `s` — сводка из хаба, `q` или `Ctrl+C` — посадить и погасить всё;
7. после посадки предлагает **забрать `flight_*` с борта**.

Полезные ключи: `--hub local` (хаб на ноутбуке), `--hub none --hub-url ...` (хаб уже
поднят кем-то), `--takeoff` (взлёт сразу после старта), `--keep-config` (не перезаписывать
`config.yaml` на борту, если правили его по месту), `-y` / `-n` (не задавать вопросов),
`--drone`, `--user`, `--dir`, `--port`.

Пульт ничего не знает сверх остальных программ — он их запускает. Если что-то ведёт себя
странно, любой шаг можно повторить руками по разделам ниже.

## 1. Из чего состоит система

Четыре программы. Запускаются **по отдельности**, обычно в разных окнах терминала.

| Программа | Где лежит | Где работает | Что делает |
| --- | --- | --- | --- |
| **Хаб** | `распределительный хаб/hub.py` | компьютер оператора | почтовый ящик: принимает пакеты от всех и раздаёт всем остальным |
| **Дрон** | `квадрокоптер/main.py` | борт дрона (или ваш компьютер в режиме заглушки) | ждёт команду «взлёт», обходит трассу, ищет станции, садится на «H», шлёт телеметрию |
| **Визуализатор** | `распределительный хаб/visualizer.py` | компьютер оператора | карта полигона со станциями и следом дрона. **Для 2.3.2 и 2.3.3 обязателен** |
| **Передатчик** | `распределительный хаб/transmitter.py` | компьютер оператора | эмулятор: играет либо за автомобиль (даёт команду на взлёт), либо за дрона (шлёт станции) |

Общаются они между собой **только через хаб**, по HTTP, порт **5001**.
Формат пакетов один на всех — `распределительный хаб/protocol/`.

> ⚠️ **Порт 5001 занят хабом.** Присланный организаторами пример визуализатора
> (`source/2_step/MapExample.py`) сам слушает 5001, и на одной машине они столкнутся.
> Наш `visualizer.py` своего сервера **не поднимает** — он тянет пакеты из хаба.
> Если на площадке визуализатор будет писать смежный трек по шаблону организаторов,
> включите мост: `python "распределительный хаб/hub.py" --forward http://<адрес>:5001`.

Дрону для связи не нужны ни `flask`, ни `requests` — всё написано на стандартной
библиотеке. Это сделано специально: ставить пакеты на борт больно (см. §8.4).

## 2. Что нужно поставить на компьютер

Нужен **Python 3.8 или новее** и три пакета:

```powershell
python -m pip install --user numpy opencv-python pytest
```

`flask` и `PyYAML` ставить **не надо** — хаб поднимется и без flask, конфиг читается сам.

На выданной на площадке машине (свои ноутбуки по регламенту 1.4 нельзя) всё то же самое
делается одной командой — она проверит окружение, предложит доставить недостающее
и прогонит тесты:

```bash
python launch.py --setup
```

## 3. Проверить, что код цел

Первое, что делается после любых правок и на любой новой машине:

```powershell
python -m pytest tests -q
```

Должно быть `127 passed` (или больше, если тестов добавилось) и **ни одного failed**.
Занимает около минуты. Если что-то красное — на полигон не идём, сначала чиним.

Тестам дрон не нужен, они проверяют логику: протокол, транспорт, оси, контур трассы,
покрытие змейки, автомат миссии.

## 4. Полный прогон без дрона (главный режим отладки)

Это то, чем вы будете пользоваться 90% времени. Дрон не нужен, полигон не нужен,
время попыток не тратится.

Нужны **три окна терминала** (четвёртое — под карту, если сдаём 2.3.2 или 2.3.3),
все открыты в корне репозитория.

### Окно 1 — хаб

```powershell
python "распределительный хаб/hub.py"
```

Должно написать `[hub] http.server на http://0.0.0.0:5001`. Оставьте окно открытым.

### Окно 2 — дрон в режиме заглушки

PowerShell (Windows):

```powershell
$env:PIONEER_MOCK = "1"
python "квадрокоптер/main.py" --task 2.3.2 --hub http://127.0.0.1:5001
```

bash (Linux/macOS):

```bash
PIONEER_MOCK=1 python3 квадрокоптер/main.py --task 2.3.2 --hub http://127.0.0.1:5001
```

Без `--task` берётся `mission.task` из конфига (сейчас `2.3.1` — облёт без детекции).

`PIONEER_MOCK=1` — это и есть «летать понарошку»: вместо настоящего SDK подставляется
`квадрокоптер/mock_pioneer.py`, который честно считает, куда бы дрон улетел.

Дрон напишет `хаб: жив`, `работаем на заглушке` и будет **ждать команду на взлёт**.

### Окно 3 — команда на взлёт

```powershell
python "распределительный хаб/transmitter.py" --hub http://127.0.0.1:5001 takeoff
```

> **Важно:** `--hub` пишется **до** слова `takeoff`. Наоборот (`takeoff --hub ...`)
> argparse не примет и ругнётся `unrecognized arguments`.

### Окно 4 — карта станций (для 2.3.2 и 2.3.3)

```powershell
python "распределительный хаб/visualizer.py" --hub http://127.0.0.1:5001
```

Откроется окно с картой полигона; станции появятся на ней по ходу облёта. Выход — `Esc`.
Если окна нет (работаете по ssh) — добавьте `--headless`, тогда станции просто печатаются
в лог.

### Что должно получиться

В окне 2 пойдут переходы состояний, а при `--task 2.3.2` — ещё и находки:

```
[main] подзадача 2.3.2 (обнаружение электростанций): detect, station_new, recon_done
[миссия] IDLE -> ARM
[flight] arm выполнен, курс старта yaw0=0.0
[миссия] ARM -> TAKEOFF
[миссия] TAKEOFF -> SURVEY
[миссия] облёт контура: 5 точек, путь 10.0 м, ~32 с
[реестр] станция d1: x=+1.20 y=-0.80 статус=ok (набл. 3, из них точных 0) ...
[реестр] станция d1 уточнена: x=+1.20 y=-0.80 статус=ok (набл. 37, из них точных 23)
[миссия] облёт завершён
[миссия] дослано уточнённых координат: 4
[миссия] recon_done: 4 станций
[миссия] SURVEY -> RETURN -> LAND -> DISARM
[миссия] завершена штатно
```

Четыре станции — это расстановка заглушки по умолчанию. Они обязаны совпасть с тем,
что задано в `PIONEER_MOCK_STATIONS` (см. §5): заглушка рисует станции той же формулой,
которой локализация потом считает координаты.

Весь прогон — примерно **минута**. В окне 3 в это время бежит телеметрия дрона.

После завершения в корне репозитория появятся два файла записи:
`flight_20260731_142530.mp4` (что видела камера) и `flight_20260731_142530.jsonl`
(что происходило с миссией).

### Прервать

`Ctrl+C` в любом окне. Дрон по `Ctrl+C` корректно садится и освобождает камеру —
не убивайте процесс через диспетчер задач, иначе камера останется занятой.

## 5. Полезные ключи запуска

### Дрон (`квадрокоптер/main.py`)

| Ключ | Зачем |
| --- | --- |
| `--task 2.3.2` | какую подзадачу сдаём (можно коротко: `--task 2`). Перекрывает `mission.task` |
| `--hub http://адрес:5001` | адрес хаба, перекрывает `config.yaml` |
| `--manual` | взлетать сразу, не дожидаясь команды от хаба (отладка без окна 3) |
| `--no-hub` | вообще не подключаться к хабу — не ждать таймаутов, когда его нет. Только вместе с `--manual` |
| `--no-camera` | без камеры и трансляции — быстрее и не мешает другим процессам. **В 2.3.2 бессмысленно**: без камеры искать станции нечем |
| `--no-record` | не писать видео и телеметрию |
| `--config путь` | другой конфиг вместо `квадрокоптер/config.yaml` |

Самый быстрый прогон «одной командой», без хаба и без камеры:

```powershell
$env:PIONEER_MOCK = "1"
python "квадрокоптер/main.py" --manual --no-camera --no-hub
```

Без `--no-hub` дрон будет честно стучаться по адресу из `config.yaml` и ждать таймаутов
(`URLError: timed out` раз в 30 ошибок). Это не поломка — транспорт по задумке не роняет
полёт, — но в оффлайн-прогоне просто тратит время.

### Хаб (`распределительный хаб/hub.py`)

| Ключ | Зачем |
| --- | --- |
| `--port 5001` | порт |
| `--log hub_log.jsonl` | журнал всех пакетов (по умолчанию пишется) |
| `--server stdlib` | не пытаться использовать flask |
| `--forward http://адрес:5001` | дублировать станции в текстовом формате организаторов на чужой визуализатор. По умолчанию выключено |

Посмотреть, что хаб видит прямо сейчас, можно браузером:

- `http://127.0.0.1:5001/health` — жив ли хаб;
- `http://127.0.0.1:5001/state` — последняя телеметрия и найденные станции.

### Визуализатор (`распределительный хаб/visualizer.py`)

| Ключ | Зачем |
| --- | --- |
| `--hub http://адрес:5001` | адрес хаба |
| `--map путь.jpg` | другая картинка карты вместо `assets/map.jpg` |
| `--headless` | без окна: только лог принятых станций. Годится, когда окна нет (ssh) |
| `--save карта.png` | сохранить итоговую карту при выходе — прикладывается к разбору попытки |

Выход по `Esc` в окне карты (как в примере организаторов) или `Ctrl+C`.

⚠️ **Привязку карты надо измерить**, иначе станции лягут не туда, хотя координаты
верны. Три числа в `config.yaml → map`: сколько пикселей в метре, в каком пикселе
картинки стоит дрон в момент взлёта, и повёрнута ли карта относительно его курса.
Пока они не измерены, помечены «НЕ ИЗМЕРЕНО».

### Передатчик (`распределительный хаб/transmitter.py`)

```powershell
# роль «автомобиль»: дать дрону команду на взлёт и смотреть телеметрию
python "распределительный хаб/transmitter.py" --hub http://127.0.0.1:5001 takeoff

# роль «дрон»: прислать 5 станций с интервалом 5 секунд — для трека автомобиля и визуализатора
python "распределительный хаб/transmitter.py" --hub http://127.0.0.1:5001 recon --stations 5
```

Роль «дрон» — самый быстрый способ проверить визуализатор, пока борта нет: подняли хаб,
подняли карту, запустили `recon` — станции обязаны появиться на картинке.

### Как подсунуть заглушке проблемы

Заглушка умеет ломаться по команде — так проверяется, что миссия правильно
прерывается. Задаётся переменными окружения:

| Переменная | Что делает |
| --- | --- |
| `PIONEER_MOCK_BATT=6.5` | стартовое напряжение батареи (порог аварийного возврата — 6.6 В) |
| `PIONEER_MOCK_DRAIN=0.02` | скорость разряда: батарея сядет прямо в полёте |
| `PIONEER_MOCK_STUCK=1` | дрон «застревает» и не долетает до точки |
| `PIONEER_MOCK_NAV_FAIL=30` | навигация отваливается через 30 секунд |
| `PIONEER_MOCK_VIDEO=клип.mp4` | вместо рисованной картинки крутить настоящее видео |
| `PIONEER_MOCK_STATIONS="1.2,0.8,ok; -1.4,0.9,broken"` | где стоят станции и в каком они состоянии (метры, наша СК) |
| `PIONEER_MOCK_STATION_SIZE=0.35x0.5` | габариты станции, м: вдоль X и вдоль Y |

Заглушка камеры рисует станции **той же дырочной моделью**, которой локализация потом
считает координаты, только обратной. Поэтому расстановка через `PIONEER_MOCK_STATIONS` —
это готовый эталон: что расставили, то и обязано прийти визуализатору.

⚠️ Чего эта проверка **не** ловит: неверные интринсики и `R_mount`. Заглушка рисует теми же
числами, которыми потом считает, поэтому любая калибровка выглядит идеальной. Настоящая
проверка — рулетка под настоящим дроном (§7.5).

Пример (PowerShell):

```powershell
$env:PIONEER_MOCK = "1"; $env:PIONEER_MOCK_BATT = "6.5"
python "квадрокоптер/main.py" --manual --no-camera
Remove-Item Env:PIONEER_MOCK_BATT      # не забыть убрать
```

## 6. Разобрать запись полёта

После каждой попытки (настоящей или в заглушке) остаётся пара файлов. Быстрая сводка:

```powershell
python tools/record.py flight_20260731_142530.jsonl
```

Покажет: сколько длилось, когда какое состояние сменилось, минимальная и максимальная
высота, как просела батарея, и была ли аварийная остановка и почему.

Видео `flight_*.mp4` — обычный файл, открывается любым плеером. Из него же режется
датасет для обучения детектора.

**Это не «на всякий случай»**: время полигона по регламенту 1.3 тратится, даже когда
вы просто стоите рядом. Каждая попытка обязана привозить материал, с которым вечером
можно работать без дрона.

### 6.1 Прогнать перцепцию по записи

Главный инструмент подбора порогов. Берёт видео и телеметрию той же попытки, гоняет
детектор и реестр и печатает, **что дрон отправил бы** — не вылетая ещё раз:

```powershell
python tools/replay.py flight_20260731_142530.jsonl
```

Пороги подбираются ключами, а не правкой конфига — иначе подобранное «на попробовать»
рано или поздно уедет на борт:

```powershell
python tools/replay.py flight_*.jsonl --set detector.min_area_m2=0.05 --set detector.polarity=dark
python tools/replay.py flight_*.jsonl --out разбор\     # кадры с рамками, посмотреть глазами
```

Что читать в выводе:

- **число станций** в «Итоговом реестре» — оно и есть критерий 8 баллов. Больше реального
  значит детектор сыпет ложными, меньше — теряет;
- пометка **`ТОЛЬКО ПО КРАЮ КАДРА`** — станция ни разу не прошла через центр кадра,
  её координата держится на худших наблюдениях. Лечится перекрытием полос (`zone.overlap`)
  или сдвигом маршрута;
- предупреждение про **незаполненные `camera.intrinsics`** — пока оно есть, «<30 см»
  по этим координатам проверять нельзя.

### 6.2 Оценить детектор по разметке

Единственный честный ответ на «стало лучше или нет». Разметка — в формате YOLO, том же,
в котором обучается модель:

```powershell
python tools/eval_detection.py кадры\ разметка\
```

Печатает precision, recall, F1, mAP@0.5 и **confusion matrix по трём статусам**.
Отдельно выделяется путаница `ok ↔ dust`: она стоит и 5 баллов подзадачи 2.3.3,
и наведения в 2.3.4 — обдувать будут не ту станцию.

## 7. Работа с настоящим дроном

### 7.1 Подключиться

1. На дроне включается своя точка доступа: сеть **`PMINI2-<UUID>`**, пароль **`geoscan123`**.
2. Подключаетесь к ней с компьютера. Дрон после этого — по адресу **`172.17.49.2`**.
   ⚠️ Документация Geoscan и опыт другой команды называют `10.42.0.1` — **у нашего
   борта адрес другой**, проверено на площадке 31.07.2026. Если не отвечает —
   посмотреть шлюз: `ipconfig` (Windows) или `ip route` (Linux).
3. Заходите по SSH, логин **`pioneermini`**:

```bash
ssh pioneermini@172.17.49.2
```

Рабочая директория на борту — `/home/pioneermini/workspace`.

### 7.4 Все настройки — в config.yaml

В коде чисел нет и быть не должно (требование регламента 2.5 — за захардкоженные
координаты и подогнанные пороги попытку могут не засчитать). Всё правится
в `квадрокоптер/config.yaml`:

- `hub.url` — адрес компьютера оператора, **обязательно вписать в день 1**;
- `loop.length` / `loop.width` — габариты трассы, **меряются рулеткой** и перепроверяются
  перед каждой попыткой;
- `loop.center_x` / `loop.center_y` — насколько площадка «H» смещена от центра овала;
- `loop.margin` — раздвинуть контур наружу (плюс) или завести внутрь овала (минус);
- `flight.h_survey` — рабочая высота, `flight.speed` — скорость;
- `flight.h_min` — жёсткий пол (0.35 м), ниже команда просто не уйдёт в автопилот.
  **Это единственная защита от касания панели, трогать в последнюю очередь.**

Змейка по прямоугольной зоне никуда не делась — включается `route.mode: survey`
и настраивается секцией `zone`. Нужна, если станции окажутся разбросаны по площади,
а не вдоль трассы.

### 7.5 День 1: калибровка камеры (полигон не нужен, 15 минут)

**Пока это не сделано, 4 балла за «<30 см» брать нечем.** Локализация работает по грубой
оценке угла обзора и при каждом старте пишет:

```
[калибровка] ВНИМАНИЕ: camera.intrinsics не заполнены, работаю по оценке ...
```

Порядок:

1. распечатать шахматку и знать её размеры: сколько **внутренних** углов по горизонтали
   и вертикали и какая сторона клетки в миллиметрах;
2. снять 20–30 кадров с борта — доска целиком в кадре, **под разными углами** и на разных
   расстояниях. Без наклонов дисторсия не считается:

   ```bash
   python3 tools/calibrate_camera.py --grab кадры/ --cols 9 --rows 6 --square 25
   ```

   Скрипт сохраняет только те кадры, где доска реально найдена;
3. посчитать и вставить напечатанный блок в `config.yaml`:

   ```bash
   python3 tools/calibrate_camera.py кадры/ --cols 9 --rows 6 --square 25
   ```

   Ошибка репроекции должна выйти меньше пикселя. Больше — переснять кадры;
4. заодно скрипт печатает настоящий `zone.fov_h_deg` — вписать, из него считается шаг змейки.

**Что остаётся после этого:** `camera.mount.*` — механический перекос крепления камеры.
Меряется отдельно и **при рабочем угле сервопривода** (`camera.servo_angle: -80`): положить
метку на известном расстоянии, снять кадр, подобрать поправки так, чтобы `tools/replay.py`
вернул реальные координаты.

### 7.6 День 1: проверка координат рулеткой (полёта не требует)

Единственная проверка, которая ловит ошибку в интринсиках и `R_mount`. Заглушка её
не ловит принципиально: она рисует теми же числами, которыми потом считает.

1. поставить дрон на подставку известной высоты, включить, дождаться `arm` (ноль СК
   фиксируется именно там);
2. положить под него станцию на измеренном рулеткой расстоянии;
3. снять несколько секунд записи и прогнать `tools/replay.py`;
4. сравнить координаты из «Итогового реестра» с рулеткой.

Расхождение больше 10 см на земле означает, что в воздухе 30 см не будет. Искать
в порядке убывания вероятности: `camera.mount.*`, интринсики, `camera.attitude.*` (знаки
крена и тангажа не проверены на нашем борту).

### 7.6.1 День 1: центрирование по посадочному знаку БЕЗ ЗАПУСКА МОТОРОВ

Проверяет ветку доводки посадки (`perception/landing.py`) на настоящей камере и
настоящем знаке «H», но **без полёта**: `arm`/`takeoff`/`land` не вызываются, винты
не крутятся (их крутит только `arm()`, а его здесь нет — создание `Pioneer` мотор не
запускает). Это способ закрыть главное «НЕ ПРОВЕРЕНО» ветки — пороги цвета `landing.*`
под реальную краску знака: заглушка рисует и считает одними числами и реальный цвет
не проверяет.

```bash
cd ~/workspace && python3 tools/check_landing.py --live
```

Держать дрон камерой вниз над знаком (или знак под неподвижным дроном), смотреть поток
`http://172.17.49.2:8889/video`: знак обведён, выведен вектор доводки «вперёд/влево, см».
Высота берётся с нижнего дальномера; если он молчит — задать руками `--live --height 1.2`.

Как читать:
- **знак не виден**, хотя он в кадре — подвинуть `landing.hue_lo/hue_hi/sat_min/val_min`
  или `min_area_px` в `config.yaml` (реальный жёлтый может отличаться от синтетики);
- **вектор скачет или указывает не туда** — знак ловится краем кадра либо неверны
  `camera.mount.*`/интринсики (та же причина, что для координат станций, см. 7.6);
- **«В ДОПУСКЕ» при знаке под дроном** — доводка сойдётся, ветку можно включать в бою.

Подвигать дрон рукой над знаком и убедиться, что захват держится и вектор ведёт к знаку.

### 7.7 Диагностика модели на борту

Если детекций **ноль без единой ошибки** — это самый дорогой случай, и вслепую он
неразличим. Скрипт печатает форму каждой сырой ветки `.rknn` и сравнивает скоры при
подаче BGR и RGB:

```bash
cd ~/workspace && python3 tools/diag_model.py --model stations > diag.txt 2>&1
```

Как читать: RGB заметно выше BGR — забыт `cvtColor`; веток не девять — виновата модель
или её архитектура в реестре (должна быть `custom`); скоры около нуля при обоих вариантах —
модель недоучена или сломана квантованием.

## 8. Заливка на дрон

### 8.1 Одной командой

```bash
python launch.py --push                    # только залить
python launch.py                           # залить и сразу запустить (§0)
python launch.py --push --drone 10.42.0.1  # другой борт; то же делает DRONE=... в окружении
```

Кладёт на борт бортовые модули, `config.yaml`, папку `protocol/`, хаб с передатчиком
и инструменты — и **сносит `__pycache__`**. `--keep-config` оставит бортовой `config.yaml`
нетронутым, если его правили по месту.

### 8.2 То же самое руками (Windows PowerShell)

```powershell
ssh pioneermini@172.17.49.2 "mkdir -p /home/pioneermini/workspace/protocol /home/pioneermini/workspace/tools"
scp "квадрокоптер\*.py" "квадрокоптер\config.yaml" pioneermini@172.17.49.2:/home/pioneermini/workspace/
scp "распределительный хаб\protocol\*.py" pioneermini@172.17.49.2:/home/pioneermini/workspace/protocol/
scp tools\record.py tools\check_sdk.py tools\check_axes.py pioneermini@172.17.49.2:/home/pioneermini/workspace/tools/
ssh pioneermini@172.17.49.2 "cd /home/pioneermini/workspace && rm -rf __pycache__ protocol/__pycache__ tools/__pycache__"
```

На борту файлы лежат **плоско** (`main.py` рядом с `protocol/`), без директорий с русскими
именами. `main.py` умеет находить соседей в обеих раскладках, так что и в репозитории,
и на борту он запускается одинаково.

### 8.3 Три правила заливки, которые стоили другой команде часов

1. **Каждый раз сносить `__pycache__` на борту.** Иначе Python возьмёт старый `.pyc`,
   и вы будете час искать, почему исправленный код ведёт себя по-старому.
2. **Никаких venv.** В виртуальном окружении `pioneer_sdk2` не работает. Ставить только
   системно (`pip install --user`).
3. **Камеру держит один процесс.** Она отдаётся через shared memory: второй желающий
   получает `TimeoutError`. Не оставляйте забытый `main.py` висеть в другом SSH-окне.

### 8.4 Хаб на борту — обход брандмауэра Windows

Штатно хаб живёт на компьютере оператора. Но если на выданной машине **нет прав
администратора**, брандмауэр Windows не пропустит входящее соединение на порт 5001,
и команда на взлёт до дрона не дойдёт. Симптом со стороны дрона — те же
`URLError: timed out`, что и при неверном адресе, так что перепутать легко.

Обход: **поднять хаб на самом дроне**. Он на стандартной библиотеке, ставить ничего
не надо, а исходящие соединения Windows не блокирует.

```bash
# окно 1 — хаб на борту
ssh pioneermini@172.17.49.2 'cd workspace && python3 hub.py'

# окно 2 — дрон ходит в хаб через localhost
ssh pioneermini@172.17.49.2 'cd workspace && python3 main.py --hub http://127.0.0.1:5001'
```

```powershell
# на ноутбуке — команда на взлёт и просмотр карты
python "распределительный хаб/transmitter.py" --hub http://172.17.49.2:5001 takeoff
# в браузере: http://172.17.49.2:5001/state
```

Минусы: хаб умирает вместе с дроном при перезагрузке, и на защите решения его сложнее
подать как отдельную сущность из регламента 2.9. Если права администратора есть —
лучше правило брандмауэра:

```powershell
# PowerShell от имени администратора
New-NetFirewallRule -DisplayName "CV_BPLA hub 5001" -Direction Inbound `
  -LocalPort 5001 -Protocol TCP -Action Allow -Profile Any
```

Проверка в обе стороны, при запущенном хабе:

```bash
ssh pioneermini@172.17.49.2 'curl -s http://<IP ноутбука>:5001/health'
```

Должен ответить `{"ok": true, ...}`.

### 8.5 Если нужно поставить пакет на борт

На борту нет интернета, пока дрон раздаёт свою точку доступа. Команда `sudo pionet`
переводит его в режим клиента Wi-Fi — и **он перестаёт быть на `172.17.49.2`**.
Ставить всё нужное в день 1 и сразу возвращать режим точки доступа.
Поэтому же бортовой код и написан без внешних зависимостей.

## 9. Настоящая попытка: порядок действий

> Шаги 1 и 3–7 целиком делает `python launch.py` (§0). Ручной порядок ниже оставлен
> как источник правды: если пульт повёл себя не так, разбираться нужно по нему.

0. **Померить трассу рулеткой и вписать в `config.yaml` → `loop`.** Длина овала вдоль
   направления «вперёд» от дрона, ширина поперёк, и насколько площадка «H» смещена
   от центра. Это делается **до** выхода на полигон, за столом. Проверить, что получилось,
   можно не поднимая дрон:
   ```powershell
   $env:PIONEER_MOCK="1"; python "квадрокоптер/main.py" --manual --no-camera
   ```
   В выводе будет строка `облёт контура: 5 точек, путь ... м` — сверьте с ожидаемым
   периметром трассы.
1. Поднять хаб. Штатно — на компьютере оператора; если брандмауэр не пускает и нет
   прав администратора, хаб поднимается **на борту** (§8.4), тогда `--hub` у дрона
   становится `http://127.0.0.1:5001`.
   ```powershell
   python "распределительный хаб/hub.py" --log hub_log.jsonl
   ```
2. Узнать IP компьютера в сети дрона (`ipconfig`; сеть нашего борта — `172.17.49.x`,
   сам дрон на `172.17.49.2`) и вписать его в `hub.url` в `config.yaml` — там стоит
   заглушка с пометкой `НЕ ПРОВЕРЕНО`. Проверка: открыть с борта
   `curl http://<IP компьютера>:5001/health`.
3. Залить свежий код на борт (§8) — и снести `__pycache__`.
4. На борту запустить:
   ```bash
   ssh pioneermini@172.17.49.2
   cd /home/pioneermini/workspace && python3 main.py --hub http://<IP компьютера>:5001
   ```
   Дрон дождётся команды на взлёт.
5. Дать команду на взлёт — от автомобиля, а пока его нет, передатчиком:
   ```powershell
   python "распределительный хаб/transmitter.py" --hub http://<IP компьютера>:5001 takeoff
   ```
6. Смотреть трансляцию в браузере: `http://172.17.49.2:8889/main_camera`
   (имя потока — `camera.viewer_name` в `config.yaml`).
7. После посадки — **забрать запись с борта**:
   ```bash
   scp pioneermini@172.17.49.2:/home/pioneermini/workspace/flight_* .
   ```
8. Разобрать: `python tools/record.py flight_*.jsonl`.

Аварийная остановка — `Ctrl+C` в окне с `main.py`: дрон сажается сам, ресурсы
освобождаются. Пульт всё равно держим в руках.

### 9.1 Что засчитывают в подзадаче 2.3.1 (5 баллов)

Запускать с `--task 2.3.1`: детекции в ней нет вообще, и ложное срабатывание не может
испортить попытку.

| Критерий | Баллы | Что для этого нужно |
| --- | ---: | --- |
| Принял сигнал от передатчика, выполнил взлёт и облёт территории | **3** | дрон стартует **по пакету**, а не по нажатию: запускать **без** `--manual` |
| Приземлился в пределах посадочной площадки | **2** | вернулся в (0, 0) и сел на «H»; замерить рулеткой отклонение |

Ключевое: `--manual` на зачётной попытке использовать нельзя. Он существует только
для отладки, когда хаба нет под рукой.

### 9.1а Что засчитывают в подзадаче 2.3.2 (12 баллов)

Запускать с `--task 2.3.2` и **обязательно с визуализатором**.

| Критерий | Баллы | Что для этого нужно |
| --- | ---: | --- |
| Взлёт и облёт + **количество станций совпало с реальным** + визуализатор показывает их в реальном времени | **8** | детектор не теряет и не выдумывает станции; карта поднята и видна экспертам |
| Координаты отличаются от реальных **менее чем на 30 см** | **4** | калибровка сделана (§7.5), привязка карты измерена, координаты сверены рулеткой (§7.6) |

Порядок сверх §9:

- **до попытки** прогнать `--task 2.3.2` в заглушке и убедиться, что число станций
  в «Итоговом реестре» сходится с `PIONEER_MOCK_STATIONS`;
- **до попытки** померить рулеткой расстояние между станциями и сверить с
  `fusion.assoc_radius` (0.40 м): порог обязан быть заметно меньше;
- поднять визуализатор **до** старта дрона — он не потеряет пакеты, если запоздает,
  но экспертам надо видеть, как станции появляются;
- **после попытки** замерить реальные координаты станций рулеткой и сравнить с тем,
  что показала карта. Это и есть прямая репетиция критерия «<30 см».

Считать по числу кружков на карте, а не по числу пакетов `station_new`: дрон дошлёт
уточнённые координаты той же станции, и пакетов будет больше, чем станций. На карте
они уточняют одну и ту же запись — она ведётся по `id`.

### 9.2 После попытки

- **Сверить баллы в таблице организаторов** — по регламенту 2.7 не позднее **60 минут**
  после попытки, иначе оспорить уже нельзя.
- **Сдать архив кода** (регламент 2.9), в конце каждого дня, имя `Название команды-число`.
  Внутри — три директории: `беспилотный автомобиль`, `распределительный хаб`, `квадрокоптер`.
  Репозиторий уже разложен ровно так, архив собирается из корня как есть.
- **Забрать записи с борта** и разобрать вечером: время полигона тратится, даже когда
  вы просто стоите рядом (регламент 1.3).

## 10. Если не работает

| Симптом | Что происходит | Что делать |
| --- | --- | --- |
| `[main] хаб ...: [Errno 111] Connection refused` | хаб не поднят или не тот адрес | поднять хаб, проверить `hub.url`; дрон при этом не падает — копит пакеты в очереди |
| Дрон молчит и не взлетает | ждёт команду `takeoff` | послать её передатчиком или запустить с `--manual` |
| Хаб на ноутбуке запущен, дрон его не видит, `timed out` | брандмауэр Windows блокирует входящее на 5001 | правило брандмауэра (нужен админ) **или** хаб на борту — §8.4 |
| `New-NetFirewallRule: Отказано в доступе` | нет прав администратора | хаб на борту, §8.4 — прав не требует |
| `transmitter.py: error: unrecognized arguments: --hub` | `--hub` написан после `takeoff` | `--hub` идёт **перед** подкомандой |
| Исправил код, а поведение старое | остался `__pycache__` на борту | `rm -rf __pycache__ protocol/__pycache__ tools/__pycache__ perception/__pycache__` |
| Станций найдено **больше**, чем стоит | детектор ловит лишнее (тень, разметка, посадочный знак) | поднять `detector.min_area_m2` и `confirm_obs`, подобрать по записи через `tools/replay.py --set`; проверить `detector.polarity` |
| Станций найдено **меньше**, чем стоит | пороги площади слишком узкие, или полосы змейки не покрыли зону | замерить станцию рулеткой и раздвинуть `min/max_area_m2`; проверить предупреждения маршрута в логе миссии |
| Две станции слились в одну | `fusion.assoc_radius` больше расстояния между ними | замерить расстановку, уменьшить радиус |
| Координаты станций смещены все разом | не заполнены интринсики или `camera.mount` | §7.5 и §7.6; в логе при старте есть предупреждение про `intrinsics` |
| Координаты станций зеркальны / повёрнуты | ошибка знака в `camera.attitude.*` или в `map.yaw_deg` | наклонить дрон рукой и сверить знак `get_orientation()`; для карты — `map.yaw_deg` |
| В логе `ТОЛЬКО ПО КРАЮ КАДРА` | станция не прошла через центр кадра ни разу | поднять `zone.overlap` до 0.5+ или сдвинуть маршрут; координата пока держится на худших наблюдениях |
| Станции на карте не там, хотя координаты в логе верные | не измерена привязка карты | `map.px_per_m`, `map.origin_px_x/y`, `map.yaw_deg` |
| Визуализатор не стартует: порт занят | пример организаторов уже слушает 5001 | наш `visualizer.py` своего сервера не поднимает — проверьте, не запущен ли `MapExample.py` вместо него |
| Детекций **ноль без единой ошибки** на борту | INT8 сломал плоскую голову, или архитектура не `custom`, или BGR вместо RGB | `python3 tools/diag_model.py` (§7.7) — он различает все три случая |
| Пульт спрашивает пароль борта на каждом шаге | ключ не лёг в `authorized_keys` | `ssh-copy-id -i ~/.ssh/id_ed25519 pioneermini@172.17.49.2` или повторить `python launch.py` и согласиться на создание ключа |
| Пульт: «хаб ... не отвечает» | хаб не поднялся на борту или занят порт | `ssh pioneermini@172.17.49.2 'pkill -f hub.py'` и запустить пульт заново; либо `--hub local` |
| Пульт вышел, а хаб остался висеть | лаунчер убили жёстко (закрыли окно) | он это переживёт: при следующем запуске увидит живой хаб и возьмёт его; на борту старые процессы гасятся сами |
| `ssh: connect to host ... timed out` | не тот адрес борта | наш дрон на **`172.17.49.2`**, а не `10.42.0.1` из документации; проверить шлюз Wi-Fi-подключения (`ipconfig` / `ip route`) |
| Камера: `TimeoutError` / `shm_open failed` | камеру держит другой процесс | найти и убить забытый `main.py`, запускать один |
| Дрон улетел не туда, в другую сторону | оси (проверены 31.07.2026, §7.3 — но борт мог смениться) | прогнать `tools/check_axes.py`, поправить `axes` в `config.yaml` |
| Контур лёг мимо разметки | не померены габариты или сдвиг «H» | рулетка → `loop.length/width/center_x/center_y` |
| Дрон прошёл контур не той стороной | направление обхода | `loop.direction: cw` вместо `ccw` |
| Дрон крутится волчком | `yaw` в градусах против радиан | `axes.yaw_units` в `config.yaml` |
| `ModuleNotFoundError: pioneer_sdk2` на своей машине | забыт режим заглушки | `PIONEER_MOCK=1` |
| Нет `flight_*.mp4`, только `.jsonl` | не установлен OpenCV или не открылся VideoWriter | `pip install --user opencv-python`; запись специально не роняет полёт |
| Тесты падают | сломана логика | на полигон не идти, разбираться на месте |

## 11. Шпаргалка

```powershell
# пульт: всё одной командой
python launch.py --mock --task 2.3.1 --takeoff        # облёт без детекции, без борта
python launch.py --mock --task 2.3.2 --takeoff --viz  # разведка + карта, без борта
python launch.py --task 2.3.2 --viz                   # борт: ключ -> заливка -> хаб -> карта -> дрон
python launch.py --push                               # только залить

# проверить код (на незанятой машине: заглушка работает в реальном времени)
python -m pytest tests -q

# прогон без дрона, четыре окна
python "распределительный хаб/hub.py"
python "распределительный хаб/visualizer.py" --hub http://127.0.0.1:5001
$env:PIONEER_MOCK="1"; python "квадрокоптер/main.py" --task 2.3.2 --hub http://127.0.0.1:5001
python "распределительный хаб/transmitter.py" --hub http://127.0.0.1:5001 takeoff

# самый быстрый прогон логики, одной командой
$env:PIONEER_MOCK="1"; python "квадрокоптер/main.py" --manual --no-camera

# проверить визуализатор, пока борта нет
python "распределительный хаб/transmitter.py" --hub http://127.0.0.1:5001 recon --stations 4

# разбор записи
python tools/record.py flight_*.jsonl                 # что происходило
python tools/replay.py flight_*.jsonl                 # что бы дрон отправил
python tools/replay.py flight_*.jsonl --set detector.min_area_m2=0.05 --out разбор\

# калибровка (без неё «<30 см» не проверить)
python tools/calibrate_camera.py --grab кадры\        # снять шахматку с борта
python tools/calibrate_camera.py кадры\               # -> блок для config.yaml

# борт (172.17.49.2)
ssh pioneermini@172.17.49.2
python launch.py --push
ssh pioneermini@172.17.49.2 'cd workspace && python3 tools/check_sdk.py'
ssh pioneermini@172.17.49.2 'cd workspace && python3 tools/diag_model.py'
ssh pioneermini@172.17.49.2 'cd workspace && python3 main.py --task 2.3.2 --hub http://<IP компьютера>:5001'
```
